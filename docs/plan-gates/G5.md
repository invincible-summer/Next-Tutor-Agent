### 后端补齐与缺陷修复（G5 期间发现）

1. **§11.6 消费 API**：图谱 overlay 带 concept_key；/knowledge/concepts/{id}?workspace_id= 返回评价 overlay；/student/profile 剥 weak/strong_points；learning-path 按 workspace 过滤；证据详情带 source_revision/interpretation_id；wrong_answer_items 带 source_id；ConceptRef.key 改 @computed_field（随一切 API 序列化）。
2. **M7 数值增益聚合清除（§13.7）**：G4 只删了 TurnTrace 字段，strategy_analyzer/schema/advisor/context_builder 残留 avg_gain 引用（`gains` 未定义 NameError、to_dict AttributeError），全部被 except Exception 吞掉导致 M7 策略数据静默变空。已修复：StrategyEffectiveness 去 avg_gain（schema/序列化）、排序改 avg_success_rate、advisor/context_builder 提示词改成功率、TurnTrace/StrategyEffectiveness 文档串修正。复现：`analyze_traces([TurnTrace(mode='socratic')])` → NameError；修复后正常。
3. **出题依据绕过证据门（§4.6，E2E Flow 5 复现）**：刚上传小文件（≤8 块）使 knowledge_search 走 allow_small_direct（不做相关性过滤），scope 外概念（ZX-999）拿到 "textbook" 依据生成伪教材题。修复：KnowledgeSearchQuizGroundingProvider 恒传 strict_relevance=True，KnowledgeSearchTool 在该内部参数下禁用 allow_small_direct（普通"总结这份文件"问答路径不变）。
4. **题卡服务端身份缺失（E2E Flow 4 复现）**：generate_quiz 的题目 dict 只有本地 `id`，注册 TaskSnapshot 后未写回，前端题卡无 question_id → 只读陈列。修复：_register_quiz_tasks 写回 question_id/question_revision，且 stash 块移到 tool_result SSE yield 之前（to_dict 按引用携带 data，SSE 负载/quiz_history/持久化历史同一身份）。
5. CAT stop 语义对齐：/assessment/start 等 wrapper 的 stop_reason=stop_code 枚举，cat.report 另带自由文本 stop_reason；前端 AssessmentSummary 双字段 + 枚举文案（sufficient_for_current_claim/needs_clarification/max_questions/max_time/user_stopped/generation_failed），旧 stop_reason.* 词条清除。

- 前端零能力计算：所有状态/判定/文案均来自后端评价 DTO + evaluation-labels 词典；
