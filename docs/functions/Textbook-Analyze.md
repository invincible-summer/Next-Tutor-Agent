# 教材解析与知识图谱生成

> Next Tutor Agent 的教材能力不是“把 PDF 上传后交给大模型阅读”，而是把教材转化为一套可以长期使用、能够被定位、检索、组织和教学消费的课程知识基础。
>
> 当前实现的主线是：**教材事实抽取 → 结构化切片 → BM25 检索索引 → 按章概念抽取 → 知识关系图谱 → 对话、出题、评价与学习编排共同使用。**

## 1. 为什么教材解析是整个学习系统的起点

对于教育智能体来说，教材并不只是一个附件。它同时承担三种角色：

1. **事实来源**：回答“教材到底讲了什么、公式是什么、定义是什么、例题条件是什么”；
2. **课程结构来源**：回答“有哪些章节、知识点之间是什么关系、哪些内容是前置知识”；
3. **学习范围来源**：回答“当前课程允许评价哪些概念、应该围绕哪些知识点出题与规划学习”。

Next Tutor Agent 因此没有把“知识库”和“知识图谱”做成两个互不相关的附属功能，而是让它们都从同一份教材事实出发：**RAG 负责找到教材证据，知识图谱负责组织课程结构。**

这一区分非常重要。RAG 擅长回答“原文在哪里”，知识图谱擅长回答“知识之间是什么关系”。二者结合后，系统既可以据实回答问题，也可以知道学习顺序、前置关系和考查范围。

## 2. 第一步：把教材还原成可引用的事实

教材上传后，系统首先关心的不是“让模型总结一下”，而是尽可能建立稳定、可追踪的教材文本。

对于普通 PDF，系统优先使用其文本层；对于文本层过稀、明显属于扫描件的教材，会按页进入 OCR 处理。教材中的图表、插图和表格也不是简单丢弃，而是尽量转成结构化的图/表描述块，与正文一起进入后续切片与检索。

系统还保留印刷页码信息。这样在回答学生问题时，可以区分“PDF 文件的第 N 页”和“教材印刷页码第 N 页”，使检索结果更接近真实的课堂引用方式。

这一阶段的核心目标不是生成“漂亮摘要”，而是得到一份稳定的教材事实源。后面的检索索引和知识图谱都从这份事实源派生，因此教材内容发生变化或索引需要重建时，不需要把整个知识体系重新想象一遍。

## 3. 第二步：结构化切片，而不是机械等长截断

传统 RAG 常见做法是按照固定字符数切块。这对百科、网页可能够用，但对教材并不理想：

- 定义可能被切成两半；
- 定理与条件可能被分开；
- 例题题干、步骤和结论可能落到不同块；
- 图表可能失去上下文；
- 章节标题与正文之间的关系会被削弱。

Next Tutor Agent 使用结构化切片，把章节、课题、定义、例题、图表和相邻文本关系尽量保留下来。切片不仅保存正文，也保留页码、章节、前后相邻关系等信息。

这带来两个直接价值。

第一，检索出来的不只是“包含关键词的一小段字”，而是更容易恢复成完整可读的教材语境。例如学生问“这一课主要讲什么”，系统可以利用课题和相邻片段把多个命中重新组织成较完整的课文上下文；学生问某个公式时，也可以取回公式所在块附近的定义和条件。

第二，同一套结构可以继续服务知识图谱。章节边界、标题和正文内容本身就是概念抽取和关系判断的重要背景，而不需要再建立一套完全独立的教材解析逻辑。

## 4. 第三步：建立可追踪的教材检索

当前教材检索以 **BM25** 为基础能力。它适合教材场景的一点在于：定义、公式名、术语、章节标题、专有名词通常具有较强的词面信号，而 BM25 可以稳定地把这些信号用于定位原文。

检索不是简单返回 top-k 文本，而是进一步判断当前命中是否真的足以支撑回答。系统把教材证据区分为：

- **FOUND**：找到了足以支撑当前问题的教材证据；
- **PARTIAL**：存在相关内容，但不足以完整支持问题中的全部要求；
- **NOT_FOUND**：在当前教材范围内没有找到足够依据。

这种分级的意义，是把“检索不到”也变成一个正式结果。对于明确要求“按照教材回答”的问题，系统不会因为大模型拥有常识就把教材里没有出现的内容包装成“教材观点”。

因此，教材检索的目标不是让模型知道更多，而是让系统清楚地区分：**哪些内容来自当前教材，哪些内容当前教材并没有提供证据。**

## 5. 第四步：从教材生成课程知识图谱

RAG 建立后，系统还会根据教材内容生成专属知识图谱。

知识图谱不是把所有名词都做成节点，而是围绕课程学习真正有意义的概念组织知识。当前流程会先识别教材的章节结构，再对各章进行概念抽取，最后把每章结果确定性合并成整本教材的知识体系。

图谱中最关键的是知识关系。当前知识层支持例如：

- **prerequisite**：前置关系；
- **related**：相关概念；
- **application**：应用关系；
- **misconception**：典型误解关联；
- 章节归属等结构关系。

其中前置关系尤其重要。系统对 prerequisite 关系保持有向无环结构，这使图谱可以真正用于“先学什么、后学什么”的推理，而不是只作为可视化关系图。

对于上下册、分册等教材，还可以把多个教材卷组织成教材组，在统一课程范围内建立跨卷知识关系。这样“上册的基础概念”和“下册的后续内容”不需要被视为两套完全无关的知识库。

## 6. 知识图谱不是展示层，而是教学系统的公共语义层

知识图谱真正的价值不在于画出一个漂亮的网络，而在于它被后续功能共同消费。

### 对话教学

当学生询问某个概念时，系统不仅能检索教材原文，还能知道该概念可能依赖哪些前置知识。如果学生持续在某个知识点上出现问题，教学策略可以回到相关前置概念，而不是不断重复当前定义。

### 出题

出题可以先定位目标概念，再从教材检索对应事实与条件。这样题目不是根据“模型印象中的这个知识点”生成，而是可以围绕当前教材真正讲过的内容设计。

### 学习评价

评价不会对整个学科做模糊判断，而是在当前教材和工作区允许的概念范围内建立学习主张。一个评价结论必须能落到明确的概念身份上。

### 学习编排

长期目标可以映射到知识图谱上的概念集合，再结合 prerequisite 关系组织学习路径。学习计划因此不只是按章节顺序机械排期，而可以考虑知识依赖。

## 7. 这一设计的关键创新

### 7.1 同一教材同时驱动“事实”和“结构”

很多系统把 RAG 和知识图谱做成两个独立工程：一个负责问答，一个负责可视化。Next Tutor Agent 的不同之处是二者来自同一教材事实，并在对话、出题、评价和编排中重新汇合。

因此，知识图谱不是一个旁路功能，而是教材事实的结构化表达。

### 7.2 先建立事实源，再让模型做抽象

教材解析不是直接让大模型“读 PDF 后总结”。原始文本、OCR、页码和结构化片段先被保存，概念抽取和图谱是其上层派生结果。

这使系统可以始终回到教材原文核对，而不是把一次模型总结永久当作事实。

### 7.3 图谱关注可教学的关系

系统重点维护前置、关联、应用和误解等教学相关关系，而不是追求构建一个尽可能大的通用知识网络。

这样的图谱更适合回答教育场景真正关心的问题：

- 这个知识点依赖什么？
- 学生卡住时应该回到哪里？
- 下一阶段应该学什么？
- 当前题目到底在考哪个概念？

### 7.4 检索证据和知识关系可以相互校验

图谱告诉系统“应该关注哪些概念”，RAG 告诉系统“教材具体怎么说”。这使知识点名称、关系和实际教材内容之间不是完全脱节的。

## 8. 实际学习体验

从学生视角看，这套教材能力最终表现为：

- 上传一本教材后，可以直接围绕教材内容提问；
- 回答能引用具体教材片段和页码，而不是只给通用知识；
- 系统知道课程中有哪些知识点，以及它们之间的前后依赖；
- 出题可以围绕当前教材，而不是随机生成“同学科题”；
- 评价能落到具体知识点，而不是只给一个模糊总分；
- 学习计划能够利用知识关系组织顺序。

因此，教材上传不是一次性“喂上下文”，而是把一本教材转化为整个学习空间可以长期复用的**课程事实层 + 课程结构层**。

## 9. 当前能力边界

当前知识检索的核心基础是 BM25；知识图谱主要服务课程概念、知识关系、评价范围和学习路径。它们承担的职责不同，不应把“图谱中存在某节点”理解为“教材中任何问题都能直接从图谱得到答案”。

对于教材原文事实，系统仍以教材检索证据为依据；对于知识之间的课程关系，则由知识图谱承担组织作用。
