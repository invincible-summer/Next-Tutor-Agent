# 对话聊天教学与语音讲解

> Next Tutor Agent 的对话不是“用户提问，大模型回答”的单轮问答，而是一条持续运行的教学链。
>
> 当前实现把 **教材依据、教学策略、学生表现、长期学习证据和下一步教学动作** 放在同一轮对话中协同工作，使聊天既承担讲解，也承担诊断、练习、纠错和后续学习状态更新。

## 1. 对话的目标不是回答，而是推进学习

普通聊天机器人往往只优化一件事：尽快给出一个正确、流畅的答案。

教育场景的目标不同。一个学生问“为什么这里要用动量守恒”，真正需要解决的问题可能是：

- 他不知道适用条件；
- 他会公式但不理解系统边界；
- 他把动量守恒和机械能守恒混在一起；
- 他只是不会当前题，并不代表概念本身不会；
- 他可能已经理解，只需要一个更高难度的迁移例子。

因此 Next Tutor Agent 把每轮对话看作一次**教学决策**，而不是一次文本生成。

系统需要同时回答三个问题：

1. **现在讲什么**：当前问题对应哪个概念、教材里有哪些依据；
2. **现在怎么讲**：是引入、解释、纠偏、练习、复习还是挑战；
3. **讲完以后看什么**：下一步要观察学生什么表现，才能知道是否应该继续、撤除帮助或换一个教学方向。

## 2. 教材在场时，先“据实”再“讲得好”

当学生的对话明确依赖教材、附件或当前学习空间中的资料时，系统会先决定本轮是否需要材料 grounding，再从授权教材范围检索相关内容。

这使对话回答具有两个层次：

- **事实层**：当前教材究竟写了什么；
- **教学层**：怎样把这些内容讲给当前学生。

两者不会混在一起。

如果教材中找到了充分证据，系统可以围绕原文解释；如果只找到部分相关内容，就不会把缺失部分冒充成教材结论；如果没有找到，系统也不会因为模型“本来知道”就伪装成教材依据。

这种设计尤其适合课堂、考试和教材辅导场景。学生真正关心的往往不是“互联网上一般怎么说”，而是“这本教材、这个章节、这个课程体系是怎么讲的”。

## 3. 讲解策略会根据学习状态切换

当前教学引擎维护六类教学模式：

- **Introduction**：第一次建立概念印象；
- **Explanation**：系统解释原理和原因；
- **Remediation**：针对错误或误解进行纠偏；
- **Practice**：通过任务巩固和应用；
- **Review**：复习、总结、梳理结构和易错点；
- **Challenge**：进入更综合、更开放或更高要求的问题。

这些模式不是前端按钮，而是系统对“当前最有价值的教学动作”的表达。

例如，一个概念目前还没有学生表现证据时，更适合建立理解；如果已有局部支持但仍有明显反例，可能优先纠偏；如果在当前范围已经有较稳定支持，则可以把教学重心转向应用和迁移，而不是继续重复定义。

因此，同一句“再讲一下牛顿第二定律”，面对不同学生不应该稳定地产生同一份模板答案。

## 4. 教学帮助不是只有“提示/不给提示”两种状态

系统显式区分三种帮助强度：

- **full_demo**：完整示范；
- **key_hints**：只给关键提示；
- **independent**：要求独立完成。

这不是纯交互设置，而是学习证据的重要条件。

一个学生在看过完整示范后复现步骤，和一个学生独立完成同类任务，不应该被解释成同样强的学习证据。系统因此会记录学生表现发生时所处的帮助条件，并在后续评价中限制推断范围。

这也让教学形成逐步撤除支持的过程：

**完整示范 → 关键提示 → 独立完成。**

其教育意义与 Cognitive Load Theory 中对初学者支持、worked example 和逐步撤除指导的思想一致。项目并不计算一个所谓“认知负荷分数”，而是把理论落实到更实用的问题上：**当前应该给多少帮助，什么时候应该把帮助撤掉。**

## 5. 学段适配改变“怎么讲”，而不是随意改变知识事实

系统支持小学、初中、高中、本科等学段，并允许自动适配。

学段信息主要用于约束讲解语言、抽象程度、例子复杂度、结构、难度锚点和典型错误，而不会因为面向低学段就改变知识本身。

例如讲“惯性”：

- 对小学阶段，可以优先从生活现象建立直觉；
- 对初高中阶段，可以进一步连接受力、运动状态和典型误区；
- 对本科阶段，可以进入更严格的参考系、模型条件和数学描述。

这种设计的重点是：**保持学科事实一致，只调整教学表达和任务要求。**

## 6. 对话中的学生表现也能进入学习评价

这是项目区别于普通问答系统的重要部分。

学生不一定只有在“测评页”里才会展示学习能力。真实学习中，大量有价值的表现发生在聊天里，例如：

- 学生主动解释为什么某个公式不能使用；
- 学生对老师的推导提出反例；
- 学生自己纠正刚才的错误；
- 学生比较两个概念的差异；
- 学生在追问中给出自己的推理；
- 学生把刚学的知识迁移到一个新情境。

系统会在对话轮结束后检查学生消息中是否出现了这种**可观察的学习表现**。

但并不是每条聊天都算证据。比如：

- “懂了”；
- “谢谢”；
- “继续”；
- “我数学一直很好”；
- “再讲简单一点”。

这些可以影响交互和教学，却不能直接证明学生会了什么。

对话评价因此关注的是学生实际展示出的理解、应用、比较、论证、纠错等行为，而不是文本长度、术语数量或自我描述。

## 7. 同一表现只归一个评价来源，避免重复记账

如果学生是在正式题卡中作答，这份表现由 assessment 流程拥有；如果学生是在自由对话中自然展示理解，则由 dialogue evaluation 处理。

系统不会因为“同一句答案既出现在聊天消息里，也属于题卡提交”就把它重复算两次学习证据。

这个设计很关键。长期学生模型最容易出现的问题之一，就是相同表现被多个模块重复放大，最终形成虚假的“越来越会”。Next Tutor Agent 的做法是让不同入口共享同一学习证据体系，同时明确证据归属。

## 8. 对话不是一次性上下文，而是持续教学记忆

一轮教学结束后，系统可以继续消费已经积累的学习证据、近期错误、教学记录和相关记忆。

因此后续对话不是从零开始：

- 之前已经反复解释过的内容，可以少重复；
- 已经证明能够独立完成的部分，可以提高任务要求；
- 仍然冲突或脆弱的知识点，可以继续验证；
- 以前有效的表达方式和交互偏好可以被延续；
- 学习计划和今日任务可以把对话重新拉回长期目标。

这种长期性让“聊天历史”不只是把旧消息重新塞进 prompt，而是逐步形成可消费的学习状态。

## 9. 对话、出题和评价是连续的，而不是三个按钮

一个典型学习过程可以是：

**学生提问 → 教材检索 → 教师讲解 → 学生解释自己的理解 → 系统记录学习证据 → 发现仍有未验证点 → 生成一题针对性任务 → 学生作答 → 更新评价 → 调整下一轮讲解。**

因此，系统可以在聊天里自然地从“讲”进入“练”，也可以从“练错了”回到“纠偏”，而不要求学生理解后台到底切换了多少模块。

这里真正重要的不是 Agent 数量，而是所有功能是否围绕同一个学生状态工作。

## 10. 语音：把同一教学链换成讲课式交互

语音功能没有建立一套独立的“语音教师”。它只是把现有对话教学换成更接近课堂讲解的交互形式。

当前语音模式采用 push-to-talk：浏览器完成语音识别，将最终文本发送给后端；后端继续走原有的教材检索、对话理解、教学策略和学习证据流程，再通过可选的 MeloTTS 进行语音播报。

因此，语音与文字模式共享：

- 同一个会话；
- 同一个教材范围；
- 同一个教学策略；
- 同一个学生学习证据体系。

语音回答还针对教学场景处理数学表达。公式可以被转换成适合朗读的表达，同时在界面中保留“黑板”式公式展示；长回答会按句子分段播报，而不是把整段文本一次性读完。

这使语音更接近“老师边讲、边把关键公式写在黑板上”，而不是普通 TTS 把 Markdown 逐字念出来。

## 11. 这一功能链的核心创新

### 11.1 “回答问题”升级为“决定下一步教学动作”

系统不只生成答案，还维护当前教学模式、帮助强度以及下一步希望观察到的学生表现。

这让每轮对话都有教育目的，而不是只追求语言质量。

### 11.2 教材事实与个性化表达分离

教材决定“依据是什么”，教学策略决定“怎么讲”。因此个性化不会以牺牲事实一致性为代价。

### 11.3 自然对话也能产生正式学习证据

学生在聊天里的主动解释、自我纠正和迁移表现能够进入统一评价体系；但系统同时严格排除“我懂了”这类没有行为证据的自报。

这让学习评价覆盖真实学习过程，而不是只依赖考试按钮。

### 11.4 帮助条件被保留下来

学生是在完整示范、关键提示还是独立状态下完成任务，会影响评价解释。这让“做对了”不再是一个脱离教学过程的二值信号。

### 11.5 语音不是外挂，而是同一教师的另一种表达介质

语音继续使用文字教学的教材 grounding、策略与评价链，因此学生切换交互方式不会切换到另一套没有记忆的系统。

## 12. 实际学习体验

从学生视角看，这套设计最终意味着：

- 可以直接围绕自己的教材提问；
- 老师会根据学习状态选择讲解、纠偏、练习或挑战，而不是每次都长篇解释；
- 系统知道什么时候应该给完整示范，什么时候只给提示，什么时候应该让学生独立完成；
- 自己在聊天里展示出的真实理解可以被长期保留下来；
- 之后的题目、学习安排和讲解方式会继续使用这些学习证据；
- 需要时可以用语音把同一套教学过程变成更接近课堂的讲课体验。

Next Tutor Agent 因此把聊天从“AI 知识问答入口”变成了整个学习闭环最主要的交互界面。
