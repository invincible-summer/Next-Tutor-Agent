# 全目录配图适配、素材审阅与素材创作通道实施计划

本文按当前 `services/api`、`apps/web` 架构编制。以下第二、三阶段在各自出口条件满足后顺序实施；未实现的条目不是现状说明。用户要求先确认配图可用，再审阅素材，最后开发创作和公私库通道。

## 一、先完成全目录配图适配

既有目录的 1,079 个素材都应能生成候选卡、按实际参数实例化并接受成图审查。31 个专门几何组件与 10 个可展开配方提供更细的端口、区域和领域检查；其余素材统一通过已登记渲染器适配，不能凭标题虚构功能。所有候选仍从本地检索产生。

采用 `diagrams/adapters.py` 统一输出参数、能力、视角、实际锚点、绘图区域、自带标注和适用限制。只将真实接线端、绳端、管口转换成连接端口；center/top 等位置锚点不能充当物理端口。示例参数仅用于候选预览。出题、需求设计提示不提供示例数字和默认读数，避免将预览条件写成题目事实。

固定图可作为一个完整构造实体；参数图的条件必须绑定合同事实。相同的材料合同、候选授权、SVG 编译、浏览器度量、PNG 视觉审查、联合审题、必要图发布门覆盖所有素材。通用适配不代表已经具有每个学科的专门证明器，无法表达的关系必须明确失败。

出口条件：全目录卡片和参数实例覆盖检查；至少跨化学、力学、测量、电路、几何、函数、统计、生物、地理、流程图的真实模型出题；改变数值与表述再测一轮；人工检查实际 PNG，问题图修正或拒绝，记录通过和失败原因。全流程默认仍按 `shadow` 渐进切换，不以一次跑通替代质量门。

## 二、全部素材截图审阅与修复

### 2.1 审阅准备

现有内置素材是代码资产，审阅输出存 `/tmp`，不写生产数据根。先导出完整 manifest，包含 ID、标题、族、版本、源码 hash、当前审阅状态、参数 schema。审核工具可以读取待审核源码渲染图；运行时检索仍必须拒绝 stale/unreviewed。不能为了截图就批量标记通过。

`apps/web/scripts/check-diagram-library.mjs` 为每个素材导出彩色、黑白 Chromium 截图，生成编号联系表、单图和 review.json。对所有实例测真实 getBBox、文字框、画布裁剪、过小文字、文字相交；对尺寸、角度、读数、计数、数组、长标签等选择参数边界和代表组合。非法组合应由参数契约明确拒绝，不算渲染成功。

### 2.2 人工审阅顺序与问题记录

逐张检查所有联系表，记录每个素材的已审阅状态。重点看形状变形、轴线与中心位置、仪器刻度、端口接触、上下支撑、透视一致性、文字相撞、标签裁剪、空间留白和自带结论。可疑项打开单图放大并定位具体图元。复用绘制函数造成的问题按素材族修正，再重跑整族和依赖模板；不能逐 ID 打补丁掩盖共性问题。

问题记录包含 asset_id、parameter_case、profile、截图位置、问题、源码修正点、复核结果。审阅不能假称人工用户已批准，reviewer_type 保持 agent。已有来源和许可证保留。

### 2.3 出口条件

所有 1,079 个素材的两个风格均有截图并逐项检查；没有未解释越界、裁剪和明显变形；参数代表用例通过或明确拒绝；修复后的素材重新截图。最后才刷新对应 review.json 的源码 hash、构建 catalog.json 与库存文档，并验证 `build_diagram_catalog.py --check`。失效的审核状态不能直接改成 passed。

## 三、公有与个人素材库、创作与上传

### 3.1 产品边界

素材库分为「公有素材」与「我的素材」。仓库内置素材归公有只读；部署新增的公有 SVG 存 `public` 命名空间，仅管理员可新增、编辑、删除。每个用户可创建个人 SVG，默认私有，其他用户无法枚举或读取。管理员也需要显式选择公有范围，个人编辑不会隐式发布。

入口包含上传 SVG、按模板手工设计、填写要求让 LLM 生成草稿。生成结果必须可以继续修改，统一经过校验和真实预览。LLM 生成不会自动保存为公开素材或自动进入出题候选库。用户显式保存并启用后才可检索；公共启用要求管理员身份。

先交付教材 SVG 编辑：源码编辑、基本图元添加、选择和调整坐标/尺寸/颜色/文字、实时安全预览、上传或拖入文件、模板和完整示例。复杂 CAD、任意脚本、外部图片、HTML、字体下载、动画与自由 SVG 插件不在本轮范围。

### 3.2 数据结构与存储

新增 runtime root `diagram_assets`，通过 `core/paths.py::bind_storage_path` 绑定，并同步登记 `orphan_cleanup` 和 StorageSandbox。

```text
diagram_assets/
  public/                    # 新增公用素材，受保护命名空间
    records/<asset_id>.json   # 当前索引、范围、标题、版本、状态
    versions/<asset_id>/<revision>.json  # 不可覆盖的 SVG 与元信息
    previews/<asset_id>/<revision>.png
  <trusted_owner_id>/        # 同结构的个人素材
```

记录字段为服务器 ID、scope、title、description、subject、aliases、revision、status、canonical_svg、content_hash、宽高、来源方式、创建和更新时间。创建/修改时不信任浏览器提供的 owner、path、审核结果、素材版本或 SVG hash。元信息使用有限长度。单个 SVG 上限 128 KiB，画布上限 960×720，有限元素/路径预算，单用户数量有界。

编辑使用 base_revision 乐观锁；冲突返回 409 并允许重新载入。每次成功编辑形成新的不可变版本。启用/停用和删除只改变索引；已经冻结的题图包含最终 SVG 和引用版本，始终可读。删除账号清理其个人索引、版本、预览和正在运行的生成；公有素材不随上传管理员删除而丢失。孤儿扫描保护 public。

### 3.3 安全与校验

SVG 用 defusedxml 解析并重新构建允许的图元、属性、变换和文本。禁 script、foreignObject、事件处理器、外链、图片、URL、动态样式和实体扩展。只接受有限渐变/引用时须经过现有规范化器的本地闭合引用校验。图片预览通过 data SVG/Image，不向页面插入未清洗 innerHTML。

上传/编辑先本地规范化，再离线 Chromium 检查实际边界并生成 PNG。错误返回有字段定位的有限错误码。保存时再次校验，不能信任前端预览结果。模板示例均为自写矢量。

LLM 生成只读用户要求、当前草稿和安全 SVG 协议，最多一次生成和一次修正，设置长度与时间预算；无任意文件、网络或素材搜索工具。模型 SVG 仅进入素材创作草稿通道，题目构图仍只能选择项目授权素材卡，不能直接提供 SVG。

### 3.4 接口合同

现有 `/diagram-assets` 继续浏览内置公用素材。新增 `/diagram-materials`：

| 接口 | 行为 |
| --- | --- |
| GET 集合，scope=public/private、q、page/per | 登录后按范围读取；共享 Pager；不返回其他用户数据 |
| GET `/templates` | 返回安全设计模板、示例 SVG、基本图元说明 |
| POST `/preview` | 校验 SVG，返回规范化预览和有限诊断，不保存 |
| POST `/generate` | 按要求/已有草稿真实调用模型，返回可编辑草稿，不发布 |
| POST 集合 | 服务器绑定范围和 owner，校验后创建新版本 |
| GET `/{id}` | 归属与范围校验后读版本及源码 |
| PUT `/{id}`，base_revision | 编辑并生成新版本；只允许本人或公有范围管理员 |
| DELETE `/{id}` | 删除当前索引，历史已冻结材料不变 |

上传接口接收文件文本或统一 SVG 字段；浏览器文件只读取 `.svg`，服务端仍检查实际内容。公有写入通过 `require_admin`，个人身份只取 `resolve_student_id`。API 请求统一 `apiFetch`。

### 3.5 出题集成

本地检索合并内置公有目录、部署新增公有素材、当前账户启用的个人素材。owner 从工具/CAT/可信上下文传递，绝不由构图模型指定。候选卡只包含本轮可读版本，编译阶段再次按 ID/版本查验可见性。

自定义静态 SVG 默认只有 static_illustration 能力，不能声明阅读仪表、液体定量绑定、电路端口或精确几何构造等未经服务端实现的功能。它可作为完整示意构造经真实 PNG 与图文联合审核；含数值、标注或关系不匹配的图拒绝。未来可增加经登记的参数化素材模板，不允许用户上传 Python/JavaScript 渲染器。

候选预览不能成为题目事实。冻结图必须保存自定义素材的不可变版本和来源。撤销启用、修改或删除素材只影响未来检索。

### 3.6 前端流程

素材库顶部提供公有/个人范围与「新增素材」。管理账户在新增弹窗可选择公有；非管理员只显示个人。新增弹窗选择上传、手动设计、AI 生成，统一进入编辑器。

编辑器显示标题/学科/说明、模板选择、基本图元工具、SVG 源码和白色纸面预览，支持预览、保存、启用状态以及清晰的失败/冲突反馈。AI 生成按钮有忙碌状态与可重试错误，用户要求保留。历史版本可查看/复制；编辑不覆盖旧版。

验证浅色、深色和窄桌面；本轮不单独开发手机适配，不更新 Github Pages 展示部署。

### 3.7 验收与上线

先运行沙箱下的身份、权限、public/私人隔离、乐观锁、不可变版本、SVG 注入/超限、账号删除/孤儿扫描、并发取消和冻结重放回归。然后真实调用配置模型生成至少科学装置、几何、流程图三类素材，检查 PNG，修改草稿并保存，用它出题并完成视觉和联合审题。公共新增以真实管理员界面验证，普通用户伪造 scope 必须拒绝。

前端运行 typecheck、ESLint、单元检查与生产构建；浏览器验证上传、模板编辑、AI 草稿、私有隔离、公有权限和编辑冲突。完成后更新现状文档、配置示例和验收报告，列出支持能力和仍会明确拒绝的情况。

## 四、素材专属约定按需加载（用户补充约束）

主提示只包含通用的合同、身份、参数事实绑定、布局、标签与质量门规范。素材专属说明分别保存于 `services/api/assets/diagram_library/materials/<asset_id>/usage_guide.json`，每份由目录绑定素材ID，含版本及 authoring/requirements/compose/review 短说明；每段最多600字。同一结构可共享绘图代码，指南仍按素材独立保存。上传用户的文本不成为系统提示。

项目先按当前题文和实体本地匹配，需求设计/出题只接收最多12份相关素材元信息及当前阶段短说明，禁止发送整个目录的特定约定。构图阶段仅本次候选（每need至多6个）携带compose说明；审图只读取最终选用的素材review说明。提示版本及指南源码hash进入重放与幂等版本。扩充素材通过增加独立指南或直接无需指南即可，不修改主提示。

逐项验证无关素材说明未进入模型输入、材料可见性、阶段隔离、预算上限，再重新真实出题和PNG复核。该步骤完成后继续收尾，最后实施新的学科覆盖扩充，禁止并行开发不同阶段。

## 五、每个素材统一隔离保存（用户补充，先于扩充实施）

内置公有素材使用 `services/api/assets/diagram_library/materials/<asset_id>/`：`asset.svg` 为原生预览 SVG，`material.json` 为元信息与登记渲染器/参数合同，`usage_guide.json` 为当前素材的简洁分阶段说明。目录索引只负责检索，不汇总发送全部子提示。多个素材即使共享绘制代码，其 SVG 和提示也各自独立；增加素材不修改主提示。参数化题图仍从登记渲染器按事实生成，不能把预览默认参数当作题目数据。完整配方也有独立包，预览连接由登记配方生成。

个人及部署新增公有素材使用 `NEXT_TUTOR_DATA_DIR/diagram_assets/<owner|public>/materials/<id>/versions/<revision>/`，同样保存 `asset.svg`、`material.json`、`usage_guide.json`，以及实际 `preview.png`。元信息不嵌入 SVG 与子提示，读取后才组装 API 响应。先写完整不可变版本，再原子更新检索索引；旧版 JSON 存储只读兼容，编辑时生成新结构版本。用户可编辑一段短使用说明，作为该素材的数据参考，不能改变参数/能力/权限或覆盖系统合同。冻结图保存所选版本及其指南版本；更新与删除只影响未来检索。

验收检查每个内置素材包可重建、索引与 SVG 一致；公私素材同目录布局、提示版本隔离、旧存储兼容、保存冲突、删除与清理均在沙箱内回归。完成结构整理及真实配图验收后，继续创作界面收尾，最后制定并实施新增学科素材覆盖计划。
